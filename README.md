# TimeWrapped

**Ваше время за компьютером — в статистике и итогах недели.**

TimeWrapped — локальное приложение для **Windows 10/11 x64**, которое показывает, сколько времени работал компьютер, какие приложения были видны на экране, какие оставались в фоне и сколько времени воспроизводился Spotify.

В конце недели приложение собирает **Weekly Wrapped**: любимые приложения, категории, ритм активности и карточку, которую можно сохранить в PNG.

**Версия:** 0.3.0 · **Стек:** Rust, Tauri 2, Win32, SQLite, JavaScript

## Возможности

- Обзор за сегодня, вчера, неделю, месяц или выбранный период.
- Отдельные счётчики времени ПК, видимых приложений, фоновой работы и запущенных процессов.
- Параллельный учёт окон на всех мониторах, включая обычные окна, открытые не на весь экран.
- Поиск приложений и фильтры «Были на экране» / «Работали в фоне».
- Отдельная карточка воспроизведения Spotify.
- Категории приложений и исключения из статистики.
- Weekly Wrapped из 9 экранов и сохранение итоговой карточки в PNG.
- Экспорт истории в JSON и CSV.
- Работа в системном трее, пауза и автозапуск без открытия окна.
- Локальное хранение данных без аккаунта и отправки истории на сервер.

## Как считается время

| Показатель | Что входит |
| --- | --- |
| **ПК включён** | Время, наблюдавшееся сборщиком, включая простой, блокировку и сон/гибернацию. |
| **С запуска Windows** | Системный uptime текущей сессии Windows, включая время до запуска TimeWrapped. |
| **На экране** | Время, когда видна хотя бы часть обычного окна приложения на любом мониторе. Ввод с клавиатуры или мыши не обязателен. |
| **Только в фоне** | Приложение работает, но его окно свёрнуто, полностью перекрыто другими окнами или отсутствует. При блокировке работающие приложения переходят в эту категорию. |
| **Запущено всего** | Общее учтённое время работающего приложения: «На экране» + «Только в фоне», без повторного учёта одного `.exe`. |
| **Активный фокус** | Время переднего приложения до наступления простоя. Порог простоя настраивается; по умолчанию — 180 секунд. |
| **Музыка в Spotify** | Время подтверждённого воспроизведения настольного Spotify через локальный аудиовыход. |

Например, за час игры на первом мониторе и открытого Discord на втором оба приложения получат по часу экранного времени. Время ПК при этом увеличится на один час. Несколько окон или процессов одного `.exe` не умножают его время.

Сумма времени приложений может превышать время ПК. Доли категорий рассчитываются от суммы экранного времени приложений. Программы, которые работали только в фоне, не попадают в топ по экранному времени.

**Сон не увеличивает время приложений и Spotify.** Пауза в TimeWrapped останавливает запись статистики. Системный uptime остаётся доступен для просмотра и не распределяется по прошлым дням как восстановленная история.

> TimeWrapped измеряет видимость окон и состояние процессов, а не внимание человека. Для статистики всего дня включите автозапуск: периоды, когда сборщик не работал, достоверно восстановить нельзя. Быстрый запуск Windows и гибернация могут продолжать прежнюю сессию ядра, поэтому uptime не является измерением электропитания ПК.

## Spotify

Счётчик увеличивается, когда Windows сообщает статус **Playing**, а у процесса Spotify есть активная локальная аудиосессия с ненулевой громкостью, без отключения звука приложения и устройства.

- Свёрнутое окно, фоновая работа и блокировка экрана не мешают учёту воспроизведения.
- Пауза и просто запущенный Spotify не увеличивают счётчик.
- Воспроизведение только на другом устройстве через Spotify Connect не считается локальным прослушиванием.
- Spotify в браузере не учитывается как настольное приложение Spotify.
- Названия треков, обложки и содержимое медиатеки не читаются.

Показатель отражает время воспроизведения: он не различает музыку, рекламу и подкасты. Если Windows не предоставляет медиастатус или не удаётся подтвердить локальный звук, приложение не добавляет предположительное время.

## Установка и запуск

Готовые сборки можно разместить в разделе [Releases](../../releases) репозитория:

- `TimeWrapped_0.3.0_x64-setup.exe` — установщик для текущего пользователя.
- `TimeWrapped.exe` — запуск без установки приложения.

Для интерфейса нужен **Microsoft Edge WebView2 Runtime**. Если он отсутствует, установщик загружает его; на этом этапе потребуется интернет. Обычная работа TimeWrapped не требует подключения к сети. Сборка 0.3.0 не имеет цифровой подписи.

После запуска откройте привычные приложения. Статистика появится в обзоре; страница обновляется каждые 45 секунд, также доступна кнопка обновления.

Закрытие основного окна оставляет сборщик в трее. Через меню значка можно открыть интерфейс, приостановить сбор или полностью выйти. Автозапуск включается в настройках.

### Обновление до 0.3

Запустите новую версию: старый сборщик штатно завершится с сохранением буфера. История и настройки сохраняются. Перед миграцией схемы 2→3 создаётся резервная копия `activity.pre-v0.3.sqlite3` рядом с базой.

Фоновая работа и музыка собираются начиная с обновления. Прежние известные интервалы видимости переносятся как минимальное время запущенного приложения; прошлые скрытые процессы и воспроизведение не восстанавливаются. Старые версии приложения не поддерживают новую схему базы.

## Приватность и хранение данных

База SQLite находится в профиле пользователя:

```text
%LOCALAPPDATA%\TimeWrapped\activity.sqlite3
```

Сохраняются имя приложения, имя исполняемого файла, категория, временные интервалы, вид учёта и количество переключений. TimeWrapped не читает содержимое ввода, заголовки окон, тексты документов, сайты, пароли и скриншоты и не отправляет историю в облако.

В настройках доступны экспорт и удаление истории с подтверждением. Исключение приложения убирает его из статистики приложений, но не уменьшает общее время ПК.

Для разработки и отдельных тестовых баз поддерживается переменная `TIMEWRAPPED_DATA_DIR`. Она также изолирует взаимодействие с экземпляром сборщика.

## Сборка из исходников

Сборка выполняется в Windows. Потребуются:

- Rust stable с MSVC toolchain для `x86_64-pc-windows-msvc`.
- Node.js 22+ и npm.
- Visual Studio C++ Build Tools с Windows SDK.
- WebView2 Runtime для запуска интерфейса.

Из корня проекта установите зависимости:

```powershell
npm ci
```

Запуск для разработки:

```powershell
npm run dev
```

Сборка EXE и NSIS-установщика:

```powershell
npm run build -- --ci
```

При стандартном расположении Cargo target результаты появятся здесь:

```text
src-tauri/target/release/TimeWrapped.exe
src-tauri/target/release/bundle/nsis/TimeWrapped_0.3.0_x64-setup.exe
```

## Проверки

```powershell
npm run check
node --test tests/ui-model.test.mjs
cargo test --locked --manifest-path src-tauri/Cargo.toml
```

Для версии 0.3.0 проходят **31 Rust-тест и 7 JavaScript-тестов**. Они проверяют независимость счётчиков, перекрытия окон, несколько мониторов, миграции, исключения, повторную запись пакетов, границы дней и переходы летнего времени.

Workflow [Windows build and test](.github/workflows/windows.yml) запускает проверки и сборку при push, pull request и ручном запуске. Установщик сохраняется как артефакт GitHub Actions.

Для длительной проверки сборщика с отдельной базой предусмотрен скрипт:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/soak.ps1 -Executable '.\src-tauri\target\release\TimeWrapped.exe' -Hours 24
```

Результаты выполненных проверок и границы тестирования описаны в [VALIDATION.md](VALIDATION.md). Ускоренная симуляция суток не заменяет настоящий непрерывный 24-часовой запуск.

## Как устроен проект

```text
src/                      Интерфейс: HTML, CSS, JavaScript
src-tauri/src/
  main.rs                 Запуск приложения и команды Tauri
  agent.rs                Фоновый сборщик, события Windows и трей
  tracker.rs              Распределение временных интервалов
  visibility.rs           Видимость окон на всех мониторах
  inventory.rs            Учёт запущенных приложений
  media.rs                Медиастатус и локальный звук Spotify
  store.rs                SQLite, миграции, статистика и экспорт
  native.rs               Нативные функции Windows
tests/                    Тесты модели интерфейса
scripts/soak.ps1           Длительная проверка сборщика
.github/workflows/         Автоматическая проверка и сборка
```

Один EXE используется для двух процессов: нативного фонового сборщика и интерфейса Tauri. Сборщик работает без WebView; интерфейс запускается отдельно. События окон отслеживаются через Win32, процессы обнаруживаются раз в 15 секунд, кешированные процессы проверяются раз в 5 секунд. Интервалы объединяются в памяти и записываются в SQLite пакетами примерно раз в 45 секунд.

Описание потоков данных, полей статистики и взаимодействия компонентов: [CONTRACT.md](CONTRACT.md).

## Ограничения

- Учёт предназначен для Windows 10/11 x64; Linux и macOS не поддерживаются.
- Видимость прозрачных, непрямоугольных, защищённых окон и нестандартных оверлеев оценивается по геометрии без чтения пикселей.
- Короткий запуск программы без окна между снимками процессов может быть пропущен; закрытие процесса определяется с погрешностью до 5 секунд.
- При принудительном завершении возможна потеря последних примерно 45 секунд буфера. SQLite WAL с `synchronous=NORMAL` не гарантирует сохранение последней транзакции при отключении питания.
- Пропущенную историю приложений нельзя восстановить из системного uptime.

## Сообщить о проблеме

При создании issue укажите версию TimeWrapped и Windows, число мониторов, масштаб интерфейса, шаги воспроизведения и ожидаемое поведение. Для ошибок учёта уточните, было ли окно видно, свёрнуто или перекрыто и воспроизводился ли звук локально.

База и экспорт содержат историю приложений. Перед публикацией диагностических файлов проверьте их содержимое.
